# ADR-0004: Grain checker fails closed; empirical execution is secondary evidence

Date: 2026-06-12
Status: accepted

## Context

Axis 2 must decide whether agent SQL inflates an aggregate through a join — without
executing it. SQL is too rich to decide statically in general: window functions, set
operations, deep nesting, and undeclared relationships all defeat sound cardinality
reasoning. A checker that guesses on those would silently trade away the property that
makes it trustworthy. Separately, an execution-based check ("run it deduped, compare")
is easy and convincing — and tempting to make primary.

## Decision

1. **Fail closed to `unknown`.** The checker has a documented supported-constructs
   fence: single SELECT; INNER/LEFT equi-joins; GROUP BY/HAVING; SUM/AVG/COUNT/MIN/MAX;
   CTEs, derived tables, and WHERE subqueries one level deep; pre-aggregation repairs.
   Anything outside — RIGHT/FULL/CROSS/SEMI/ANTI joins, USING, non-equi or unqualified
   join conditions, window functions, set ops, UNNEST/LATERAL/PIVOT/QUALIFY, deeper
   nesting, undeclared relationships or tables, cyclic join graphs, DISTINCT inside
   SUM/AVG, unsupported aggregates — returns `unknown` with the construct named. Never
   a guess.
2. **Fan-out model: per-source BFS over the oriented join tree.** Each equi-join edge is
   oriented one→many from declared GrainModel cardinalities (or inferred for
   pre-aggregated derived tables, which are unique per their group keys). For
   tree-shaped graphs, a source's rows are duplicated exactly when a walk away from it
   crosses an edge in the one→many direction. This single rule catches the fan trap,
   the chasm trap (two 1:N legs from a shared parent), and the dimension-measure trap
   (summing a parent attribute across a fact join), while leaving star/snowflake
   queries clean. The naive alternative — flag only the direct one-side of each edge —
   was tested and rejected: it misses chasm inflation outright.
3. **Verdict vocabulary is actionable.** `unsafe` (SUM/AVG of a duplicated source, with
   the offending path and aggregate in evidence), `needs_distinct` (COUNT of a
   duplicated key — syntactically trivial fix), `safe`, `unknown`. MIN/MAX are
   duplicate-insensitive → safe. COUNT(*) is unsafe only when *no* source is
   duplicate-free (result grain matches no declared table — the chasm shape); counting
   a well-defined many-side grain is legitimate and is reconciliation's job to value-check.
4. **Empirical cross-check is secondary, never the verdict.** `empirical_inflation`
   re-runs a query with the fan side deduplicated and reports the ratio. It is used in
   tests and as report evidence. It cannot be primary: it requires execution (the
   static guarantee exists precisely to avoid that), a dataset (its answer holds only
   for the data it ran on), and it inherits whatever is wrong with the data.
5. **Precision is published, not promised.** The labeled corpus (47 queries: 15 traps,
   20 clean, 12 fence) is the spec; the test suite prints TPR / FPR / unknown-rate on
   every run and asserts the gates (TPR ≥ 0.90, FPR ≤ 0.05). Measured at acceptance:
   TPR 1.000, FPR 0.000, unknown rate 0.255.

## Alternatives

- **Execute-and-compare as the primary check** — rejected (point 4); kept as evidence.
- **Full relational-algebra cardinality inference** — rejected: research-grade
  complexity for marginal v1 gain over the fence + `unknown`.
- **Regex/heuristic SQL inspection** — rejected: unauditable and dialect-fragile.
- **Guessing on out-of-fence constructs** — rejected: one confident false `safe`
  costs more credibility than any number of honest `unknown`s (RT-002).

## Red-team

- **Failure modes:** alias/CTE mis-resolution (mitigated: sqlglot `build_scope`,
  probed before design; naive `find_all(Table)` provably mis-resolves); FPR creep as
  repair recognition gets fancier (mitigated: the corpus gates both rates in CI).
- **Edge cases:** composite join keys (grouped per alias pair), quoted identifiers,
  alias renaming (tested invariant), LEFT joins (multiplication unaffected by
  null-extension), singleton subqueries.
- **Security:** parse-only; no execution path exists in the primary module.
- **Scalability:** linear in AST size; measured well under the 50 ms/query budget.
- **Maintainability:** every fence extension must arrive with corpus rows; the
  printed precision numbers make regressions visible in CI logs.
- **Register:** RT-002 (incompleteness → publish rates) upheld; RT-012 added —
  pre-aggregation recognition is heuristic; mitigated by corpus coverage of repaired
  variants (grouped and DISTINCT forms, both worlds).

## Consequences

- Easier: the module is a generic gate (SQL + GrainModel in, verdict out) — the seed
  of the standalone CI-gate product; evidence strings name the exact join path for the
  report's failure gallery.
- Harder (accepted): a quarter of realistic queries land in `unknown` at v1 fence
  width; widening the fence is deliberate, corpus-gated work (Snowflake dialect and
  deeper nesting are post-launch).
