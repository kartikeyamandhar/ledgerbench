# ADR-0003: Scoring rules — tolerance, exact counts, and fail-closed semantics

Date: 2026-06-12
Status: accepted

## Context

Phase 2 freezes the contracts and the deterministic scorer for the definitional,
ambiguity, and refusal axes. Every threshold and edge rule in a scorer silently becomes
part of the measured construct, so each one must be explicit, configurable where it is a
judgment call, and documented where it is a policy. A wrong default here poisons every
later result, which is why these rules get their own ADR and a revisit note.

## Decision

1. **Relative tolerance, default 0.5%, per item override.** A numeric value passes iff
   `|agent − gold| ≤ t·|gold|` with `t = 0.005` unless the item overrides it
   (`tolerance_override`). Relative, not absolute, because business metrics span orders of
   magnitude; scale-invariance is verified by a property test. The boundary is inclusive.
2. **Integer count metrics match exactly.** A metric with `value_type: count` is a
   cardinality; "off by one" is wrong, not approximately right. `42.0` passes for `42`
   (integral float form is fine); `42.4` and `41` fail.
3. **Gold of exactly zero requires exactly zero.** Relative tolerance is undefined at
   zero. Fail closed with an explicit `zero_gold_exact` rule in the evidence rather than
   inventing an absolute-epsilon fallback nobody agreed to.
4. **Clarifications must reference the actual ambiguous term; refusals must name the
   actual missing dimension.** Matching is normalized (case, underscores/hyphens/spaces)
   substring-or-all-words. Without this, generic hedging ("could you clarify?", "I cannot
   answer") would pass the behavioral axes. `Item` therefore carries `ambiguous_term` /
   `missing_dimension` — an addition to the original contract sketch, required to make the
   check mechanical.
5. **Malformed agent output scores zero and never raises.** `parse_agent_response`
   returns `AgentResponse | MalformedResponse`. Strictness is directional: requests we
   produce forbid unknown fields; responses agents produce ignore extra fields but are
   strict on types and action-specific requirements (`answer` ⇒ `value` + `sql`,
   `clarify` ⇒ `clarifying_question`, `refuse` ⇒ `refusal_reason`). Numeric strings
   coerce ("48200.5" is accepted); garbage does not.
6. **Fail-closed aggregation.** `unknown` counts against the agent in an axis's pass
   rate; `na` axes are excluded and weights renormalize over axes that applied. Item
   roll-up precedence: fail > unknown > pass > na. Weights are validated (finite,
   non-negative, not all zero) and echoed in every output.
7. **Exceptions are reserved for our bugs.** Non-finite gold, fractional count gold,
   negative tolerance, or an ambiguity/refusal expectation missing its term raise
   `LedgerBenchError` — these are item/config defects that must stop a run, not score it.

## Alternatives

- **Absolute tolerance** — rejected: not scale-free; a 0.5-unit error means nothing
  without knowing the metric's magnitude.
- **Epsilon band at gold = 0** — rejected: any epsilon is arbitrary and silently encodes a
  unit assumption; exactness is defensible and overridable per item if a future world
  needs it.
- **Raising on malformed responses** — rejected: turns an agent failure into a run
  failure; the contract is "malformed = zero on all axes for that item" (RT-008).
- **Treating `unknown` as `na`** — rejected: it would let an undecidable case quietly
  improve a score; fail-closed keeps the incentive honest and the `unknown` rate is
  reported, not hidden.
- **Free-text judging of clarifications/refusals** — rejected for these axes: the
  mechanical term/dimension check is auditable and deterministic; semantic judging is
  confined to the faithfulness axis (Phase 5), where it is double-run and flagged.

## Red-team

- **Failure modes:** tolerance default wrong for some metric family → per-item override
  exists; revisit the default after the first real benchmark runs (register RT-011).
  Term-matching too lenient/strict → normalized matching tested in goldens; rubric text
  gives human reviewers the intended reading.
- **Edge cases:** boundary-inclusive tolerance, NaN/inf agent values, sign flips,
  integral-float counts — each is a named golden fixture.
- **Security:** agent output is data; no eval, no dynamic dispatch on agent strings.
- **Scalability:** scoring is arithmetic; 1000 verdicts aggregate in well under a second.
- **Maintainability:** 100% branch coverage is enforced per-module in CI (`cov-core`), so
  any new branch in scorer core must arrive with its tests.

## Consequences

- Easier: scores are explainable from evidence alone; re-scoring old traces is exact;
  third parties can validate responses against the exported JSON Schemas.
- Harder (intentionally): contract changes now require ADR + schema re-export + version
  bump; the golden suite must be extended, never silently edited.
